# 软件测试体系：设计讨论

> 状态:草稿（2026-09-10）。当前仅调查与讨论，不修改测试实现；问题优先级、目标范围与迁移方案尚未确认。

## 已确认的目标与边界

用户希望重新设计和实现项目的测试体系，并在过程中学习软件开发中的测试。范围为软件行为、接口契约及故障处理的验证，不涉及模型任务质量评估。先通过实际问题确定改造范围，不预设替换 Bun、全部重写测试或建设通用测试平台。

当前阶段维护本讨论稿；形成明确取舍后再编写规格、实施批次和验收方案。通用测试术语在讨论中解释，不加入只维护 Forge 领域概念的 CONTEXT.md。

## 初步事实与证据

- `package.json`：使用 `bun test`；`bun run check` 组合依赖边界检查、类型检查与测试。静态检查与运行测试是不同的验证手段。
- 测试既分布在 `packages/*/test/`，也分布在根目录 `tests/` 和 `scripts/*.test.ts`；目录位置本身不足以判断测试边界。
- `packages/cli/test/session-preview.test.ts` 通过真实会话文件验证预览和缓存；`tests/tui-integration/session-management.test.ts` 启动正式 CLI，通过 PTY 驱动交互并使用本地模型响应。
- `scripts/test-headless.ts` 使用受控执行端口调用 CLI 入口，检查正常退出；它不能独立证明真实供应商连接正确。
- 本轮尚未重新执行测试、统计稳定性或测量分组耗时，不根据历史通过数量断言现有体系充分或需要推倒重写。

## 与现有决策的关系

- ADR-006/007 当前约束：TUI 使用 cell 回归及仓库内 golden，不以 PNG 零差异为硬门禁，不编译 grok-build 作为测试前置。若候选方案改变这些原则，需明确重新讨论，不能用目录整理隐式替代。
- ADR-010/013/014 的输入归属、保存与上下文契约，以及 ADR-015 的内核接入边界，是现有测试应保护的产品行为；测试体系调整不自动授权改变这些行为。
- SOP 要求与改动相称的验证、反向验证及区分自动化/人工证据；本轮先保留。运行分组、测试辅助设施、失败报告及维护方式仍可讨论。

## 决策树与当前待决问题

1. 首要问题：学习与可理解性、回归可信度、运行与维护成本，哪项是本次改造的主要驱动？等待用户说明具体场景。
2. 在问题明确后讨论：需要保护的关键行为与测试边界、真实依赖和替身的选择。
3. 再讨论：测试组织、执行入口、失败诊断与 CI 分工，是否确需新增辅助框架。
4. 最后确定：保留与迁移范围、实施批次、验收方法与学习路径。

推荐先围绕 `/resume` 的一个行为走通“需求 → 用例 → 准备输入 → 执行 → 断言 → 引入缺陷验证 → 回归”，以具体经验支持后续设计；此建议尚未作为实施决定。
