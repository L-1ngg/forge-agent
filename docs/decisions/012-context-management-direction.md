# ADR-012: 上下文管理方向

> 状态:被 [ADR-014](014-pi-aligned-context-management.md) 取代；保留逐项讨论记录，不再作为当前施工规格(2026-09-07)
> 参与者:operator、Codex。

## 背景

当前 `ExecutionCore` 累积消息，并在每次 `driver.stream()` 时交给模型适配器；`pi-port` 加入 system prompt 和工具定义。现有 usage 统计不驱动压缩或超限恢复。模型超限错误会结束本次执行，不能自动恢复任务连续性。

operator 在方案访谈第一轮确认三个推荐方向，原话：“上面的方案都同意，然后在此之前，我需要你去调研一下pi和claude code在这个大问题上的决策”。本决策只记录已确认方向，不把后续调研建议当作已批准实现。

## 决策

1. 上下文不足时自动缩减并继续当前任务；第 15 项将初稿的压缩失败一律停止改为按触发场景处理：请求前主动压缩失败可沿用当前上下文请求，超限/length 恢复压缩失败则停止该次恢复。用户取消和存储写入失败仍停止。本批不纳入进程重启后的任务自动恢复。
2. 已提交会话历史保留原文，模型上下文允许使用摘要与近期原文；被省略信息应能按引用找回。查找接口、保存形式及未提交内容的保存时机另行设计。
3. 允许压缩使用额外模型调用并自动执行；第 18 项将调用边界对齐 pi：固定摘要流程及单请求有限重试，不另设每次压缩或 invocation 的累计摘要调用额度。确定性的内容缩减可与模型摘要配合；累计 usage 仍可观察，但不承诺整个长任务的摘要费用有固定上限。
4. 上游调研后，operator 认可组合方向：每次模型请求前准备上下文、控制工具结果体积、按合法消息边界摘要、保留可查原文、超限后有限恢复。具体保留集合、任务内切分规则、阈值、摘要模型和存储接口继续访谈，不将方向认可视为实现细节全部获批。

### 原文保留与任务内切分

第二轮访谈的用户原文固定保留规则，已由 operator 在 pi 逐项对比第 3 项确认改为 pi 的可摘要规则；其余边界保留：

- `systemPrompt` 始终原样提供。当前 `runTurn()` 的初始用户请求和已消费的 `steer` / `followUp` 不再作为不可摘要锚点；落在保留边界之前时允许进入摘要，近期消息仍按原顺序保留。
- 按 pi 的方式保留连续近期消息；切在当前用户 turn 中间时，将此前历史与该 turn 被省略的前缀分别摘要，再合成为历史摘要与 `Turn Context (split turn)`，接上近期原文。摘要应保留任务目标、有效约束、进度及要求的冲突或替代关系，但不承诺逐字保真。
- 原始用户消息仍按既定提交规则保存，并可按引用找回；取消用户原文固定保留不改变原始历史及引用契约。没有合法切分或摘要材料仍无法装入时停止本次压缩，不静默截断需求；普通任务是否继续按第 15 项区分主动压缩与失败恢复。
- 允许在同一任务内压缩已经完成的步骤。时机是整批工具完成并形成配对结果之后、下一次模型请求之前；不切分正在生成的响应或尚未完成的工具批次。
- 同一 assistant 消息中的工具调用与对应结果作为完整单元处理，不留下孤立结果。保留近期完整消息，较旧步骤及用户输入可转为摘要。
- 摘要记录已执行动作、证据、未解决问题和后续工作。压缩不重放已完成工具；需要时通过引用补查旧细节。

近期原文保留采用下文已确认的 pi 策略；跨多次压缩的覆盖范围提案见配套设计第 2 节，作为后续整体审核内容。

### 大工具结果、原文找回与摘要模型

operator 确认第三轮推荐选择，并在解释单条与整批预算后确认以下方向；在 pi 逐项对比第 7 项再次确认保留工具自身限制与内核统一单条/整批预算：

- 工具结果采用有限正文、明确省略提示和原文引用。单条设上限；同一轮全部工具结果的合计还受估算可用空间约束，分配时考虑系统提示、工具定义、历史及适配器实际输出/推理配置。该估算用于限制工具正文，不构成普通任务请求的额外硬准入门槛，也不保证供应商精确装入。具体数值和批内分配算法继续收敛，删除依赖旧 B 的配额公式；访谈中的 8000/20000 tokens 只是示例。
- 内核预算同样适用于宿主自定义工具，缩减模型可见正文；工具自身的资源限制和确定性预览规则仍可保留。此统一预算是 Forge 的补充，不等同于 pi 内置工具各自截断；它不能消除工具生成巨大结果时的内存开销。
- 每次工具调用仍有对应结果，不因体积预算直接删除某条 `toolResult`。普通工具原文指实际交给内核的结果；Bash 另外在采集层保存超过预览限额的输出，见下文存储升级与输出范围。其他工具在交付前已丢弃的数据不能由内核恢复。
- 提供模型可调用的按引用分页读取工具，首版不做语义检索。摘要及被省略的工具结果携带引用，找回结果同样受上下文预算限制；引用保存期限和未提交内容归属见后续已确认小节，具体接口见配套设计。
- operator 在 pi 逐项对比第 8 项确认保留会话引用及模型分页找回方案；阅读 [Bash 输出归档调研](../research/pi-bash-output-archive.md) 后曾确认长期归档，随后因长期磁盘累积成本明确改为 Bash 完整输出临时文件。会话消息原文找回与临时日志分开，不再承诺完整日志随会话长期保存。
- Bash 捕获层采用超阈值懒落盘，在系统临时目录下创建日志文件，补足写入背压、I/O 错误处理和完整性状态。临时日志用于当前及后续轮次补查，清理方式按下文采用 pi 默认方向；具体额度与异常处理继续收敛，不表示开始代码实施。
- 首版摘要使用当前主模型，不增加独立摘要模型配置。摘要使用独立请求，只生成摘要、不执行工具，并设置输出和重试上限；独立请求形状见后续已确认小节，不承诺同模型即命中缓存。

### 压缩触发、近期保留与失败恢复

第四轮的“触发线与目标比例分离”选择，已被 operator 在 pi 逐项对比第 1 项中的明确指令“这一项决策上，改为Pi的方案”替代；后续第 12 至 15 项进一步修订失败恢复和普通请求行为：

- 采用 pi coding-agent 固定预留策略：默认 `reserveTokens = 16384`，当 `contextTokens > contextWindow - reserveTokens` 时触发主动压缩。默认 `keepRecentTokens = 20000`，按合法消息边界保留约该量的近期原文，其余可压缩历史生成摘要。
- 删除设计初稿中的输入预算 90% 触发、65% 压缩目标及按输入预算 20% 缩放近期原文量的规则。压缩后的大小由摘要和保留内容决定，不另设总量目标比例。
- 第 1 项仅修订触发与近期保留策略；用量估算已在下文第 2 项另行确认，用户输入可摘要范围已在第 3 项修订，摘要输出上限已在第 4 项确认；第 9 项改为逐步持久化，见 ADR-013。`reserveTokens` 不等同于实际请求输出上限。
- 第 14 项 operator 确认“按 Pi 的方式处理普通任务请求”：取消独立的 `B = W - O - M` 硬准入门槛，以及初稿额外的 M 余量和普通请求 `min(model.maxTokens, 16384, floor(W / 4))` 输出上限。普通任务采用固定预留触发、pi-ai 适配器输出限制，以及已确认的单次超限/length 恢复；宿主显式输出配置仍经适配器映射。
- 系统提示和工具定义仍完整提供，消息按合法边界保留或摘要，不破坏工具配对或静默截断需求。压缩候选仍须通过摘要有效性、覆盖和配对校验，但不因估算仍高于触发线而拒绝发布或普通请求，不将触发线改作硬准入线。工具正文配额与独立摘要请求的输入/输出预算继续保留；压缩失败按下文第 15 项处理。
- 只有有效摘要才替换活动上下文；生成失败或输出被截断的摘要不发布为成功结果。
- 摘要调用遇认证等不可重试错误时停止该次压缩，临时网络或服务错误按第 17 项有限重试；最终失败后是否继续任务按第 15 项处理。普通任务请求自身的认证等不可重试错误仍停止任务，不因此获得压缩恢复。第 18 项取消额外的累计摘要调用额度。
- 供应商报告上下文超限时，允许一次压缩并重新请求模型，不重放已完成工具；同一恢复链重试仍超限时停止并报告原因。第 16 项删除仅凭压缩未释放空间或频繁触发就停止的规则。
- pi 逐项对比第 12 项确认取消“已有实质输出则不恢复”的初稿限制：响应被明确识别为上下文超限错误时，即使已有部分输出也允许一次压缩重试。失败尝试保留历史，重试请求排除该失败响应；已展示内容标明失败/恢复，不能伪装为从未输出或保证从断点续写。已完成工具结果保留，失败响应中的调用不执行。
- 正常完成的回答若被用量判定为超过配置窗口，保留回答并压缩后续上下文，不重复生成。用户取消不自动恢复，普通网络错误不因有部分内容就视为超限。
- 第 13 项确认 length 恢复也原样采用 pi coding-agent 的比较基准：`stopReason === "length" && model.maxTokens > 0 && usage.output < model.maxTokens` 时，允许一次压缩后重新生成。基准为模型最大输出，不采用此前提出的本次配置输出上限；即便宿主主动设置较小输出上限也可能触发，接受这条启发式判定不保证压缩有效。
- length 与明确超限共用一次恢复机会，不因原因切换而分别重试。截断响应保留为历史，从本次重试上下文移除，不保证从断点续写；已有工具结果保留，不重放工具。普通 length 不因第 11 项而被全局过滤，是否恢复按本条或明确超限判定处理。
- 第 15 项 operator 确认采用 pi 的压缩失败继续策略：普通请求前的主动压缩没有可压缩材料或摘要生成/校验失败时，保留当前有效上下文，报告未压缩的原因后继续尝试任务请求；不发布无效摘要，也不在同一次请求准备中反复压缩直至成功。第 18 项取消分块兜底及累计调用额度，摘要输入超限同样走本条失败处理。
- 明确超限或可恢复 length 之后，只有恢复压缩成功才发起已批准的那一次重试；压缩失败或无材料均停止该次恢复，不原样重试失败请求。主动压缩失败后发出的任务请求若再明确超限或符合 length 条件，仍按共同的一次恢复规则处理，不能获得无界重试。
- 第 15 项仅改变压缩未完成后的任务续跑规则。用户取消仍停止任务；会话消息或压缩记录写入失败仍按 ADR-013 停止调度并停用实例，不将存储异常吞成可继续的摘要失败。此存储边界是 Forge 已确认的补充，未照搬 pi 自动压缩中统一捕获保存异常的处理。
- 第 16 项 operator 确认采用 pi 的压缩发布和重复触发方式：有效摘要可保存并继续任务，不要求压缩后估算 token 数严格减少；删除初稿连续三次快速再触发即 `context_thrashing` 停止的提案。压缩前后估算用于观察，不据此判断任务是否有进展。
- 每次请求准备只尝试一次主动压缩操作，不循环压缩直至低于触发线；操作内部按第 18 项采用固定摘要流程与单请求有限重试。最新分支记录已经是压缩且没有新增记录时跳过重复压缩；有新材料后按正常触发条件重新判断，不使用初稿额外的材料版本封锁规则。旧压缩边界前的 usage/error 不能触发当前恢复，usage 有效性仍按 Forge 已确认的统一规则检查。
- 一次恢复限制针对连续失败链，不是整个 invocation 只能恢复一次。按 pi 的重置时机，新的 user 消息实际进入执行流，或任务 assistant 以非 error/length 终态完成时，后续失败可获得新的恢复机会；摘要完成本身不重置任务恢复计数。队列尚未消费的输入不提前重置；累计 usage 不随恢复计数重置而清零。
- 第 17 项 operator 确认摘要沿用主任务重试配置，未配置时采用 pi 默认 `enabled = true`、`maxRetries = 3`、`baseDelayMs = 2000`，即首次调用加最多三次重试，默认等待 2/4/8 秒。主任务显式禁用重试时摘要也不重试；等待和后续调用可取消，不另设一套摘要专用重试配置。
- 仅对识别为临时故障的单次摘要调用重试，例如网络中断、限流及分类器覆盖的服务端错误；取消、认证/额度等永久错误、摘要 length 截断及内容校验失败不进入该重试。历史摘要已成功而 turn 前缀摘要失败时只重试后者，不重跑已成功的摘要步骤。
- 所有首次调用与重试都累计次数及 usage，供观察核对；第 18 项取消将累计计数作为停止条件。底层 provider 自动重试关闭，由内核统一控制并计数；此摘要重试不增加任务超限恢复次数、不执行工具。删除初稿的单摘要仅重试一次、500ms 延迟和 Retry-After 最多等 5 秒的独立规则；最终失败按第 15 项处理。
- 失败的压缩不得先破坏已有上下文；已经保存的消息及有效摘要按 ADR-013 保留，不因本次压缩失败而回滚。尚未完成的记录不承诺已持久化。

### 上下文用量估算

operator 在 pi 逐项对比第 2 项确认“也采用pi的方案”，并要求核对 pi 是否在压缩、切换模型或改变 system prompt / 工具定义后使旧 usage 失效或重新核算。

- 采用最近一次有效 assistant usage 加其后新增消息估算的方式；优先 usage.totalTokens，否则按 input、output、cacheRead、cacheWrite 合计。无可用 usage 时才回退到文本字符数除 4 等启发式估算，不宣称精确 tokenizer。
- 删除设计初稿中每次重新按 UTF-8 bytes / 3 估算完整请求、实际 usage 只用于观察的选择。
- 本项目的 usage 复用必须与当前请求材料相符：压缩、切换模型、改变 system prompt 或工具定义后，旧依据须失效或重新核算。[固定源码核对](../research/pi-context-management.md#后续核对usage-的失效范围) 确认 pi 只有局部保护，没有覆盖这些变化的统一机制；operator 在了解该差异后确认保留 Forge 的有效性检查。首版失效后回退完整候选材料的启发式估算，直到取得新的有效任务 usage，不做跨模型换算。
- 原始历史中的 usage 作为历史证据保留；“失效”表示不能继续充当当前请求的计量依据，不删除历史用量。摘要请求的 usage 也不能直接作为任务请求的依据。

### 摘要输出上限

operator 在 pi 逐项对比第 4 项确认采用 pi 的分类型输出上限：

- 历史摘要请求的 `maxTokens` 为 `min(floor(0.8 * reserveTokens), model.maxTokens)`；当前 turn 前缀摘要为 `min(floor(0.5 * reserveTokens), model.maxTokens)`。
- 默认 `reserveTokens = 16384` 且模型上限足够时，分别为 13107 与 8192 tokens。这是请求输出上限配置，不是目标摘要长度，也不是一次 compaction 的合计输出或成本上限；供应商的推理与输出映射须在适配层计量。
- 删除初稿统一 `min(4096, model.maxTokens, floor(W / 8))` 的摘要上限。第 18 项取消通用分块与模型合并请求，不再设置其额外输出预算。
- 摘要截断不发布、调用有界等既定行为保留。摘要推理配置见下文第 5 项。

### 摘要推理配置

operator 在 pi 逐项对比第 5 项选择默认继承、允许显式关闭：

- 未单独配置摘要推理策略时，沿用当前主任务的推理配置，与 pi 的默认方向一致。
- 显式配置摘要关闭推理且当前模型/供应商支持时，摘要请求使用 `off`；主任务的推理配置不因此改变。此覆盖选项是 Forge 的补充，不描述为本次已核对的 pi 默认行为。
- 删除初稿摘要一律请求 `off` 的规则。不将“支持推理”等同于“支持关闭推理”，也不将最低推理等级称为关闭；适配器按实际生效配置计入输出和推理预留。
- 显式配置关闭但模型不支持时，回退主任务的推理配置，继续摘要；在摘要事件中记录实际生效的配置及回退原因。operator 已确认该兜底规则，不把未生效的关闭请求报告为已关闭。

### 提交、取消与压缩期间的输入

第五轮的整次 invocation 成功统一提交规则已由 pi 对比第 9 项改为 [ADR-013](013-incremental-session-persistence.md) 的逐步持久化，压缩期间输入时序保留：

- 消息和工具结果随执行逐步保存，有效摘要及重建边界独立保存；不等待整次 invocation 成功。仅候选摘要及尚未开始保存的材料保留暂存性质。
- 取消或执行失败保留已保存的本次历史、摘要和引用，不恢复至 invocation 开始前的历史；不自动恢复未完成任务，也不回滚工具外部副作用。第 10 项已确认缺少工具结果时仅在请求视图补错误提示，表明结果缺失与执行状态未知；原历史不改、不重放工具，具体规则见 ADR-013。
- 第 11 项确认 error/aborted assistant 的已获得内容和状态可保存为历史，但下一次任务请求跳过整条中断响应；更早的完整消息及真实工具结果保留，不把 length 自动归为同一种情况。此过滤不触发自动重试，取消仍停止执行。
- 保存接入执行循环的可等待边界，任一写入失败停止继续调度并停用实例。已开始写入按 ADR-010 保留原则等待结果，不承诺撤销宿主写入。成功保存的摘要在重建 Agent 时可加载；具体存储接口与一致性机制待施工设计。
- 摘要针对启动时固定的上下文生成。压缩期间继续接收归属于当前 invocation 的干预，不因每条新输入重启摘要；队列中的输入不提前标记为 processed。
- 摘要成功后，steering 在下一次任务模型请求前按既有 FIFO 消费，follow-up 保持既有较晚消费时机。新增输入进入上下文后重新检查预算。
- abort 同时取消摘要与本次执行，等待清理，不再自动发起下一次任务模型请求。

### 引用生命周期与摘要请求

operator 确认第六轮推荐边界，Q14 经请求形状解释后确认：

- 已提交原文引用跟随所属会话保存，重建 Agent 后仍可读取，同一会话后续压缩不使旧引用失效。引用指向当时保存的内容，不以工作区当前文件冒充历史结果。
- 上述长期保证适用于保存到会话的消息正文、摘要及工具预览；Bash 完整输出临时文件按下文规则允许过期，不属于长期原文引用。临时文件失效不使已保存会话记录无法加载。
- 本次已经保存的原文引用不因取消或失败失效；尚未保存的材料及其引用不承诺跨重建有效，已开始写入的结果按存储收尾核对。首版不给长期会话引用单设过期时间，清理所属会话时一起清理；Bash 临时日志按下文独立规则处理。
- 首版采用独立摘要请求：摘要专用指令、已有摘要和本次待压缩原文，不携带原任务的工具定义或完整编码 system prompt。仍使用当前主模型，不提供可执行工具。
- 摘要输入与输出都纳入预算，不假设摘要天然装得下；原对话缓存复用优化留待后续，不宣称独立请求已被证明费用更低。

### 存储升级与输出范围

Q15 的存储升级选择保留；Q16 的 Bash 输出范围经第 8 项调研后扩展，并最终收敛为临时日志而非长期归档：

- 接受升级 SessionStorage 契约，以保存原始消息及摘要、覆盖关系和引用；自定义 SDK storage 需要同步适配。首版不长期维护两套写入逻辑。
- 旧会话通过显式转换生成新格式副本，保留源文件作为回退依据，不自动覆盖旧文件。具体转换接口、格式和验证规则由施工设计确定；本次确认不表示现在执行数据迁移。
- Bash 小输出可保留在消息正文；超过预览阈值时创建临时日志，补写此前缓存的原始字节并持续写入后续采集输出，模型只接收有限预览、临时读取位置及完整性状态。不将全部日志塞入模型请求或 JSONL 消息正文。
- 成功、非零退出及超时的 Bash 结果均能携带日志读取信息；命令失败不等同于整次 invocation 失败。会话保存消息、摘要和有限预览；日志文件不参与 SessionStorage 的持久提交，不提供跨重开长期可用保证。
- 临时日志支持按需读取，避免为一页加载全文；读取时检查文件可用性，文件缺失明确返回日志已过期或不可用，不能以当前工作区内容替代。读取入口继续设计。需要长期保留的报告或产物由任务显式写入指定文件。
- operator 最终确认沿用 pi 默认清理方式：应用不在 invocation 结束、取消/失败或退出时主动删除 Bash 日志，不设置 TTL 或启动清扫；由系统或用户清理，保留跨轮次补查机会。终止采集时仍关闭写入并释放句柄，不能以保留文件为由泄漏运行资源。文件仍需存在且可访问，不保证永久保存，也不保证系统及时清理或累计磁盘占用有界；单命令资源上限另行决定。
- 日志写入失败时必须明确标记不完整，不能声称完整输出；资源额度及异常时是否继续命令仍待设计收敛，不自动采用会话累计或全局配额。“完整”限于采集期间实际收到的输出，不承诺取消后未产生的数据，也不能补回旧版本已经丢弃的数据。
- 内核为了上下文预算省略的普通工具正文仍须可找回；Bash 临时日志过期不削弱已保存会话消息的找回保证。

### 摘要流程与首版交互

operator 曾在 Q17、Q18 及 pi 逐项对比第 6 项确认通用有界分块；在第 18 项比较累计调用额度和分块差异后明确指令“都采用Pi的方式”，本小节据此替代此前分块与累计调用额度方向：

- 采用 pi 默认结构：历史摘要加可选的 turn 前缀摘要；无对应材料则跳过该部分，最多两个逻辑摘要请求，按来源先后执行。两部分成功后直接按固定文本结构拼接，不发起第三次模型合并请求。
- 删除通用局部摘要、单层模型合并、递归分块及其参数提案。历史/turn 前缀切分是固定的语义分工，不是任意超大输入都能装下的分块兜底。摘要输入超限或其他生成失败时，不发布半成品；按第 15 项区分主动压缩继续任务与恢复压缩失败停止恢复。
- 取消每次 compaction 6 次和每次 invocation 32 次累计摘要调用额度，不以另一组累计常量替代。每个逻辑摘要仍有第 17 项的有限重试，默认各最多四次尝试；两个摘要都执行时默认结构至多八次模型调用入口尝试。这是结构推导，不是额外配置的八次总限额，也不是任意自定义适配器底层 HTTP 次数保证。
- 后续需要压缩时重新执行固定流程，不因此前任务累计调用达到某数而禁用摘要。累计次数与 usage 仍上报；有限重试约束单个请求，不能据此承诺无限长任务的总耗时和费用有界。本项不修改已确认的工具正文配额、原文引用、推理配置及存储故障规则。
- 首版交付自动压缩及必要观察能力。SDK/CLI 输出结构化压缩、恢复和失败事件，TUI 显示简短状态并保持输入和停止可用。
- 手动 `/compact`、摘要编辑器及上下文管理面板不纳入首版范围。

## 被否方案

| 方案 | 本轮不选择的原因 |
|---|---|
| 仅提示用户开新会话 | 不能满足当前任务自动续跑的目标 |
| 摘要覆盖原始历史 | 摘要遗漏后无法核对原文 |
| 每次压缩都请求许可 | 将内部容量管理反复变成用户操作 |
| 只做机械裁剪 | 不足以保留长任务中的目标、约束和决策 |
| 同批引入重启后自动恢复 | 涉及执行检查点及工具副作用，不属于本轮已批准范围 |

## 后果

会话历史与模型上下文需要区分；术语见根目录 `CONTEXT.md`。这意味着不能只在当前消息数组上删除旧消息就认为完成方案。

pi 与 Claude Code 的一手资料比较见 [上下文管理调研](../research/context-management-comparison.md)。已确认方向的设计整合及尚待审核的实现选择见 [上下文管理设计草稿](../phases/context-management.md)。调研建议和草稿参数不自动成为已批准决策。

当前实现仍沿用原 ADR-010 的整次提交行为；目标设计已按 ADR-013 修订为逐步持久化，ADR-010 的输入归属及写入不可撤销原则保留。新方向不等于已实现上下文管理；施工设计、路线优先级调整和代码实现仍待后续确认。
