# ADR-013: 会话逐步持久化

> 状态:有效部分已按 [ADR-014](014-pi-aligned-context-management.md) 实现并完成本地验收；历史引用找回与损坏行处理方向被其部分替代(2026-09-07)，见[实现证据](../phases/context-management-acceptance.md)。
> 参与者:operator、Codex。

## 背景

在上下文管理的 pi 逐项对比第 9 项中，operator 询问“如果我想要改为pi的方案呢？”，在了解取消保留历史、未完成工具配对及执行中存储失败的影响后确认改为逐步持久化。

当前 [AgentRunner](../../packages/core/src/agent-runner.ts) 收集整次 invocation 的消息，仅在正常结束、未取消且工具配对完整时调用 appendTurn。长任务中途停止会放弃本次过程记录，但已经发生的工具副作用不会回滚。随着任务内自动压缩和长工具循环引入，这一差异会增大。

pi 的 coding-agent 在 message_end 追加消息、压缩成功后追加 compaction 记录；首个 assistant 前存在延迟 flush，不能泛化为每个 token 或每个事件立即刷盘。固定证据见 [pi 调研](../research/pi-context-management.md)。本决策采用逐步保存方向，不强制复制上游缓冲细节或整个 AgentSession。

## 决策

本节记录逐项确认时的边界；具体保存时序、文件容错及模型查回能力以 [ADR-014](014-pi-aligned-context-management.md) 和当前施工方案为准，不再将后文“继续收敛”作为未决行为。

- 用户输入进入执行上下文、模型消息完成、工具结果形成时，按执行顺序逐步保存；失败工具结果也属于历史。不等待整次 invocation 成功，不逐 token 持久化。
- 有效摘要及覆盖/保留边界作为独立记录保存；候选摘要仍须全部生成并校验成功，不保存半成品为有效压缩。已经成功保存的摘要不因后续任务失败而撤销。
- 取消停止后续执行，保留已经保存的消息和摘要；不退回 invocation 开始前的历史。不承诺尚未完成或未开始保存的内容一定落盘。
- 保存应接入执行循环中明确、可等待的边界，不能只在公开事件消费者中异步追加而允许内核继续启动后续动作。记录串行追加，不因并行工具完成顺序产生无序写入；具体调度接口待施工设计。
- 任一存储写入失败，停止继续调度并停用实例，由宿主核对实际存储状态后重建。已经开始的写入不可保证取消，抛错不代表零写入；不能盲目重试追加，也不回滚工具外部副作用。
- ADR-010 的输入归属、FIFO、未消费输入返还宿主、processed 表示已进入上下文等规则保留；processed 不升级为持久化确认。尚未启动的 invocation 被取消仍不启动模型、工具或存储写入。
- dispose/abort 等待必要的执行与写入收尾；agent_end 仍表示执行终止，正常迭代完成还需等待必要保存完成。任务成功不再是唯一保存入口。
- SessionStorage 从整次 appendTurn 演进为消息与压缩记录的有序追加契约；具体类型、存储格式与事件先后关系在设计稿中收敛。Bash 临时日志仍不参与持久提交。

## 替代范围

本决策部分替代 [ADR-010](010-input-ownership-and-interruption.md) 第 3 节的整次 invocation 提交与提交前取消不保存规则，以及其中针对该规则的旧验收断言；输入归属和写入不可撤销等其他原则继续有效。

[ADR-012](012-context-management-direction.md) 的整次 invocation 暂存、成功统一提交及取消放弃所有本次引用的选择同步替换为本决策。已有实现及过去测试结果仍描述旧行为，本次方向确认不表示已完成代码迁移或 SDK 交付。

## 缺失工具结果

operator 在 pi 逐项对比第 10 项确认：采用 pi 的请求视图补齐方式，原始历史不改、不重跑工具。

- 对已完整形成并保留的 assistant 工具调用，已有真实结果原样保留；缺少对应结果时，只在后续请求视图中补一个标为错误的合成 toolResult，关联原调用 ID。
- 提示明确表达“结果未记录，无法据此确定是否已执行或产生副作用；继续前应检查当前状态，不要仅因结果缺失直接重复执行”。不是工具成功、未执行或回滚的证据。
- 合成结果不追加到原始会话历史，不覆盖真实结果，不发起旧工具调用；后续模型生成的新调用仍走正常执行与权限规则，不宣称提示可以保证模型不会重发。
- 原始历史可包含未完成调用，不据此判为损坏文件。发模型请求前才校验/补齐协议配对；任意非法 ID、跨分支引用及物理损坏仍需拒绝，不因这一规则放宽。
- 正在执行的当前工具批次仍等待终止或收尾，不为了提前发下一请求而给运行中的工具补缺失提示。该规则处理的是历史中缺少结果的调用。

该选择对应 pi-ai 的请求转换机制，细节与供应商适用范围见 [源码核对](../research/pi-context-management.md#后续核对未完成工具调用的请求转换)。Forge 需要在自己的请求准备路径保证生效，不盲目依赖特定 pi-ai 版本或供应商的隐式修补。

## 中断模型响应

operator 在 pi 逐项对比第 11 项确认：保留中断记录，但下一次任务模型请求跳过它。

- 模型响应以 error/aborted 结束且已获得可保存的部分内容时，保存原始内容及失败状态供历史查看；不把它标为成功回答，不逐 token 写盘，也不承诺进程崩溃前未保存内容可恢复。
- 后续任务请求跳过整条 error/aborted assistant，包括其部分文本、推理块及未完成工具参数，不把其中工具调用当作可执行指令。原始记录仍保留，供历史查看及按引用核对。
- 已有更早完整消息和真实工具结果不因过滤该响应被撤销，工具外部副作用不回滚。正常完成工具调用但结果缺失的情况仍按上一节补结果提示，不与响应本身中断混淆。
- 本项只适用于 error/aborted，不自动扩展为 length、任意非 stop 终态或任意工具失败。取消不因此自动重试，是否发起后续请求仍服从执行调度与恢复策略。

## 后续决策与限制

- 历史可能停在 assistant 工具调用之后、部分工具结果之前；按上节已确认规则生成请求视图，不擅自写入伪造成功结果。
- 没有工具结果不等于工具未执行；不得自动重放历史工具来补齐记录。历史保存不自动提供进程崩溃后的任务续跑或外部副作用一致性。
- 中断 assistant 的历史保留及后续请求过滤已确认；取消时已形成但未写入结果如何收尾、用户输入的首次写入顺序及并行工具结果记录时机，需要在上述方向下收敛。
- 单条追加的物理损坏与工具结果尚未形成是不同状态；不因允许未完成历史就允许忽略损坏文件。

## 被否方案

| 方案 | 原因 |
|---|---|
| 整次 invocation 成功后才保存 | 中途停止丢失过程记录，与实际已发生的工具动作不一致 |
| 仅监听公开事件并在后台写盘 | 不能保证写入失败时执行循环已停止推进 |
| 通过重新执行旧工具补齐历史 | 工具可能已有副作用，不能依据缺少结果推断未执行 |

## 后果

保留中断任务的证据与进度，代价是需要表达未完成历史、在循环中处理存储失败，并增加追加操作次数。执行完成与历史保存不再共用一个最终事务边界。
