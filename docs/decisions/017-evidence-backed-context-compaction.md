# ADR-017: 可追溯的任务状态与有界上下文压缩

> 状态:已批准(2026-09-12)，替代范围仅适用于显式启用的 adaptive。
> 参与者:operator、Codex。

## 背景

[Issue #31](https://github.com/L-1ngg/forge-agent/issues/31) 要求保留关键任务状态、按相关性选择材料、追溯与重建摘要、动态控制压缩预算，并分别验证软件合同与真实模型质量。用户已要求实现、验收后提交 push 并关闭 Issue；本 ADR 将规格未固定的架构选择具体化，按 [SOP](../SOP.md#改动分级) 在写码前确认。

现有 [ADR-014](014-pi-aligned-context-management.md) 采用历史摘要与近期原文，不维护独立状态、不提供历史找回、不要求压缩后满足下一次请求预算。原始记录保存及工具执行生命周期继续适用。

## 决策

### 1. 以有来源的状态检查点承接语义，而非关键词猜测

采用同一主模型提取结构化状态及摘要；状态是从原始记录派生的检查点，摘要是压缩叙述，二者分开存储与装配。每个状态项保留类型、内容、来源消息及必要原文片段、替代关系。状态类型覆盖目标、约束、决策、授权陈述、计划、阻塞、下一步；事实/推测分别标记。

检查来源属于选中分支、引用原文确实存在、替代对象可解释；结构或引用失败时不发布检查点。该检查不能证明语义提取无遗漏，因此新增且尚未完成提取的用户消息原文受保护，模型忠实度另行评估。新纠正与任务切换由提取器显式返回变更，再验证其来源，禁止仅以“最后一条覆盖所有历史”实现。

执行成功、失败、缺失结果及验证记录由 runtime 保存的证据产生。提取器只可把这些记录关联到语义任务，不得制造“已执行”“测试已通过”。授权陈述只用于提醒任务上下文，不能成为权限判定输入。

取舍：不采用自然语言关键词正则充当通用语义理解，也不要求 SDK 宿主手工提供所有状态。需要一次有预算的模型提取；短任务保持原文，无需每轮调用提取器。

### 2. 增强策略显式选择，原策略保留为对照与回退

在现有 context 配置中增加策略选择 `strategy: "pi" | "adaptive"`，初次交付默认 `pi`。`adaptive` 承担本 ADR 的新合同，关闭自动压缩仍允许手动压缩。真实模型验收通过后也不在本任务中默默修改默认策略。

状态保存在 compaction 记录的可选、带独立版本的增强载荷中；不新增与消息并列的任意记录类型。原始消息和 parentId 分支继续使用 v4。增强载荷携带可复现的保留消息 ID、工具文本裁剪描述、状态、摘要引用及更新计数；加载时验证，不接受未知版本。普通 summary 字段保留可读降级内容，旧 reader 无法重放增强投影，回退只承诺使用新版本的 `pi` 模式。

### 3. 以完整交互单元选择上下文，以分支限定原文找回

最新待处理用户原文、未归档状态变更及正在推进的交互单元优先保留。较老材料按状态引用、当前任务词项重合度、时效排序；相同内容仅在同一角色及相同工具调用语义下去重。工具调用与对应结果按一个单元选择，不能产生孤立结果。

工具原文裁剪仅修改请求投影，并保留记录 ID、结果状态及可找回标记。只对可确认重复或可重新获取的正文裁剪，关键错误和执行封套不删除。取舍是采用可解释的本地排序，不额外引入 embedding 服务或 relevance 模型。

提供内核所有的 `read_context` 工具，限定当前选中会话分支，只读取已保存消息的文本片段；不接受任意文件路径，不跨会话搜索。工具经现有 hooks/权限和取消边界执行，正文按 Unicode code point 分页并限制 UTF-8 字节，支持超长单行续读，不恢复尚未存入历史的正文。宿主已有同名工具时明确拒绝配置冲突。引用缺失/越界返回错误，绝不读取最新文件冒充历史。

### 4. 以预算与有限进展控制请求，定期重建检查点

所有 adaptive 任务请求与摘要请求先按其实际装配内容计量，预留请求输出额度和估算余量。已有有效任务 usage 可作锚点；投影改变后失效。估算不是物理窗口保证。

先尝试低成本选择，足够时不摘要；仍不足再进行一次状态/摘要生成，复算后最多执行一次原文重建。一次压缩操作有固定模型调用上限，包含重试，达到上限或无进展即明确失败；不降级为无约束发送。预算不足时保留旧有效检查点和全部原始消息。

达到连续增量更新阈值、明确任务切换、或检测到结构化状态冲突时重建。仅检测可表达的冲突，如同一状态项同时 active/superseded、替代链循环、同一执行记录被标记为不相容结果；不宣称发现任意自然语言矛盾。相关原文超过单次预算时明确失败并说明需要缩小任务材料，本版不建设通用层级摘要器。

### 5. 软件合同与模型质量分别准入

复用公开 SDK、本地 HTTP provider、存储重开和可计数工具作为主测试边界；真实模型在冻结任务集上比较 `pi` 与 `adaptive`。质量未过不宣称改进，验收不足不关闭 Issue。具体预算、样本和门槛见施工图。

## 对 ADR-014 的替代范围

仅在本 ADR 获批准并实现后，对 adaptive 替代下列取舍：纯时间连续后缀、没有关键状态、没有模型历史找回、固定阈值与不要求压缩后空间、没有累计调用上限、主动压缩失败后继续发送过大请求。`pi` 保持原合同。

继续保留：原始历史追加保存；runtime/Agent 是唯一执行内核；工具批次收尾后处理；取消不重放；存储失败停用；usage 失效；旧会话只在副本上转换；恢复会话不自动重启工具。通用 RAG、Team、日志永久归档与权限升级仍不在范围内。

## 后果

新策略可以稳定保留结构与证据，无法以代码校验证明摘要语义完全正确。更多检查和提取会增加短任务开销，因此先裁剪、按需提取、保留显式策略选择。状态越积越多可能无法满足预算，此时明确失败而不静默丢约束。

实施落点、切片、真实模型门槛与回退见 [施工图](../phases/adaptive-context-compaction.md)。批准后更新 ADR-014 的替代指针与 SDK 中英文说明；本草稿不提前宣称旧方案已被替代。
