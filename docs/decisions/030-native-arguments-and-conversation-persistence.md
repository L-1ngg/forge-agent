# ADR-030: 原生参数审批与普通会话保存

> 状态:已实现并完成本地离线软件验收(2026-10-01)。operator 已确认简化方向；施工与验收见[施工图](../phases/session-middleware-simplification.md)。真实供应商、跨平台和崩溃恢复未测。

## 背景

operator 指出执行前保存屏障、审批改参后的重复校验与复判属于过度设计。它们维护了强于普通单 Agent 会话所需的副作用证据保证，也让采用 TanStack 原生审批后仍需维护一条独立的参数处理链。

## 决策

- TanStack `chat()` 继续拥有工具串行执行、schema 校验及 `interrupt/resume`。Forge 从原生待审批项取得已校验的参数，计算一次 `allow / deny / ask`。宿主 `editedArgs` 直接进入原生 resume，不再由 Forge 重新判权、比对参数或写审批修订记录；人工批准同时授权编辑后的调用。
- Zod/官方工具直接使用原生 Standard Schema。动态 JSON Schema 通过官方 MCP Ajv 的薄 Standard Schema 接口进入同一原生校验路径，保留基本类型、必填和额外字段检查。工具自己检查路径、资源、文件状态等业务条件。
- 删除没有生产调用的 `prepareArguments`、`toolInputRewrites`、通用 `validateArguments` 以及重复终检链。`beforeToolCall` 观察参数副本并可以阻止调用，`afterToolCall` 仍可覆盖工具结果；参数转换放在工具内部。
- 工具执行期间记录内存中的实际结果，批次结束后按提案、调用顺序的结果保存，再请求下一轮模型。取消时等待已开始工具清理并保存已得结果；不启动后续工具。存储失败仍报告错误、停止请求并停用实例，不自动重试追加。
- 不再承诺工具副作用发生之前已保存提案或最终参数，也不承诺逐工具结果保存可以阻止同批后续副作用。进程崩溃可能丢失最新批次；保存失败时效果可能已经发生。恢复会话仍不重放旧工具。
- 保留输入归属、配置快照、原始协议审计、完整请求预算、普通历史和权威终态接线。现有会话格式、分支与证据引用继续使用；旧参数修订记录仍可读。OTel 与 `ai-persistence` 接入另行决定，本次不升级依赖。

## 取舍与替代范围

保留旧屏障可以增加执行前证据，但维护成本不符合当前需求。普通会话保存允许明确的崩溃丢失窗口，减少状态和校验职责。`ai-persistence` 0.7.1 要求 `@tanstack/ai ^0.63.0`，当前 0.61.0；本次不为了保存时序引入版本迁移及第二份 transcript。

本决定替代 ADR-013、024、025、026、027、028、029 中与执行前/逐工具保存屏障、通用参数改写、审批编辑复判和修订记录有关的部分，其余决策保留。原审批取消、配置及原始响应合同继续生效。
