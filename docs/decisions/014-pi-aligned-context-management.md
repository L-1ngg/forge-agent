# ADR-014: 对齐 Pi 的上下文管理

> 状态:已实现并完成本地自动化及受控真实任务验收，未推送或发布(2026-09-07)；见[实现证据](../phases/context-management-acceptance.md)。
> 参与者:operator、Codex。

## 背景与替代范围

operator 在逐项比较后要求：“剩余还有和上下文工程相关的，请你都直接和pi对齐吧，然后整理一下方案”。此决策结束逐项访谈，按固定源码快照统一剩余行为；不将方案整理视为运行代码实施授权。

基准为 `earendil-works/pi` 的 coding-agent，SHA `9767ba275f3e9a5ee0f5c5342249b629ab1b2282`；不是新的 AgentHarness，也不要求升级整个上游应用。Forge 当前 `pi-ai` 为 0.84.4，执行循环仍由自研 ExecutionCore 拥有。

本决策取代 [ADR-012](012-context-management-direction.md) 的当前方案入口，历史比较记录保留；并补充 [ADR-013](013-incremental-session-persistence.md) 的保存时序和格式，替代其中模型按历史引用找回、损坏行一律拒绝等与本文冲突的方向。ADR-013 的逐步保存、取消保留、请求修补及存储失败停用继续有效。完整施工与验收只维护在[上下文管理方案](../phases/context-management.md)。

## 统一决策

| 范围 | 最终选择 |
|---|---|
| 执行位置 | 每次任务模型请求前准备上下文；响应后识别超限/length 并有限恢复。工具批次未结束不压缩 |
| 主动触发 | 默认启用；`contextTokens > W - 16384`；保留约 20000 tokens 近期原文，按 Pi 合法切点选择 |
| 计量 | 最近有效任务 usage 加后续增量估算，无依据时回退字符启发式；不设置普通任务硬准入 B/M |
| 摘要结构 | 历史摘要及可选 turn 前缀摘要，最多两个逻辑请求，直接拼接；旧 user 可摘要；没有通用分块或模型合并 |
| 摘要材料 | 独立摘要 system、文本序列化对话、旧摘要更新模板；每个工具结果文本在摘要输入中只保留前 2000 个 JS 字符并标记省略 |
| 摘要输出 | 历史 `floor(0.8 * R)`、turn 前缀 `floor(0.5 * R)`，模型声明正的 maxTokens 时再取较小值；不以压缩后变小作为发布条件 |
| 调用设置 | 当前主模型、路由及重试策略；摘要 cacheRetention 为 none；默认重试三次，2/4/8 秒退避 |
| 调用总量 | 无每次压缩/每次任务累计额度，无频繁压缩停止规则；记录次数与 usage |
| 自动失败 | 主动压缩失败沿用当前上下文尝试任务；恢复压缩失败不重试；不循环压缩到阈值以下 |
| 失败恢复 | 明确 overflow 与 `length && model.maxTokens > 0 && usage.output < model.maxTokens` 共用连续失败链的一次恢复；部分输出不排除恢复 |
| 工具输出 | 工具自己截断；删除内核统一单条 token 配额、整批再分配及最小封套预算机制；自定义工具自行控制结果大小 |
| Read / Bash | 默认预览 2000 行 / 50 KiB，Read 取头、Bash 取尾；Read 用 offset/limit 按行读取，Bash 大输出懒写系统临时日志 |
| 日志生命周期 | 无单文件、会话或全局日志配额，无 TTL、退出删除或启动清扫；普通 Read 补查日志，系统/用户清理 |
| 原文找回 | 保留原始会话记录供宿主查看/导出；取消专用 read_context、持久原文分页引用和工具全文归档平台；不承诺模型自动找回摘要遗漏 |
| 会话重建 | JSONL 消息/压缩追加记录及 parentId 分支；最新 compaction 的 summary + firstKeptEntryId 后保留消息 + 后续消息 |
| 手动入口 | 增加 SDK compact 与 CLI `/compact [instructions]`，先停止当前执行并等待空闲，手动完成后不自动续跑旧任务；可关闭自动压缩 |

这里的“工具自己截断”也替代 ADR-012 第 7 项额外内核预算；“原文找回”替代第 8 项专用模型读取工具。原始历史没有被删除，但已被工具自身丢弃的正文不因此恢复。Read 是当前文件内容，不能称为历史快照；Bash 临时日志也不升级为持久会话资产。

## 保留的项目约束

以下是 operator 已明确选择的要求及现有 SDK 边界，保留并标记为 Forge 差异，不冒充 Pi 完整具备：

1. 压缩、模型/provider/API、system/tools、消息投影或分支变化后，旧 usage 必须失效；没有有效依据时完整回退估算，不跨模型换算。无 usage 覆盖的 system/tools 计入估算。
2. 摘要推理默认继承主任务；允许单独选择关闭，模型不支持 off 时回退继承并报告。其余摘要模型、重试与路由不另建独立配置体系。
3. 消息/压缩写入必须处于循环可等待的边界；写入失败停止新调度并停用实例，不照搬 Pi 保存异常被自动压缩 catch 吞掉的行为。SDK 输入归属、FIFO、processed 含义、未启动取消零工作保留。
4. 缺失工具结果仅在请求投影补错误提示，明确执行/副作用未知；不重放工具。error/aborted assistant 保存原始内容但请求整条过滤；不把截断工具参数当作可执行调用。
5. 保留最基本的 I/O 错误处理、取消和资源释放：日志写失败按工具失败报告，不承诺继续命令或完整日志；读取失败不影响会话加载。不复制未处理 stream error 等实现缺陷。写入背压与错误收尾属于实现质量，不引入日志配额/恢复平台。
6. 不原地覆盖 operator 的旧会话。采用 Pi 追加记录与容错读取思路，但版本升级只转换副本；不承诺 Forge 与 Pi JSONL 二进制或类型兼容。

## 保存和操作边界

- 用户输入进入上下文时保存，完成 assistant 在工具调度前保存；并行工具结束后按调用顺序保存已形成结果，随后才进入下一模型请求。不照搬 Pi 首个 assistant 前延迟刷盘的内部优化，不把 SDK 写入成功降为纯内存缓冲。
- 取消时不再启动新模型/工具；等待在运行的工具收尾，保存已形成的最终消息/结果，写入失败则停用实例。不承诺进程崩溃时尚未形成或写入的数据可恢复。
- 文件加载逐行解析，坏 JSON 行可跳过并报告；不因缺失工具结果拒绝历史。有效 header 和可解释的选中分支仍是使用前提，坏行导致分支或压缩边界不可重建时明确拒绝该视图，不伪造历史。读取不自动修复源文件。
- `enabled = false` 禁用主动压缩及 overflow/length 自动恢复；手动 compact 仍可执行。关闭自动压缩不关闭工具自身截断。
- compact 的自定义 instructions 作为历史摘要的 Additional focus，不覆盖摘要 system，也不当作主任务新输入。公开事件采用 Forge 的 SessionEvent 体系，覆盖开始、结束、失败、重试和恢复，不复制 Pi 整套扩展框架。

## 删除的额外机制

不再实现严格输入准入公式、比例压缩目标、用户原文固定锚点、通用分块摘要、模型合并、摘要累计额度、context_thrashing、内核工具批内 token 分配、read_context、Bash 长期归档/配额/自动清理，以及持久化任意工具正文切片投影。

不因对齐上下文策略新增 Team、RAG、全套 Pi 工具集合、扩展 hook 平台、会话分支自动总结、摘要编辑器或进程重启后自动执行。已有 read/write/edit/bash 工具承担当前实施范围；若以后新增 grep/find/ls，按相同上游工具自身限制方式处理。

## 后果与证据

机制和状态显著减少，主要路径接近 Pi；代价是工具整批输出、长任务累计费用、临时日志磁盘占用不具有全局固定上界，超大摘要输入也没有分块兜底。模型可能遗漏摘要细节，原始记录可查看不代表模型会自动读取。
